# MoonshineCFSG: unconditional monstrous moonshine for AxiomMath's Monster

A small Lean library, separate from `VOA`, built on top of it. Its headline is
`MoonshineCFSG.MoonshineLRCFSGBridge`: `gmatEqAutO`, `monsterEquivAutVnat'`, `monsterEquivAutVnat'_restrict`,
`monstrousMoonshine_unconditional`. It needs AxiomMath's proof `gmat_eq_griess` (the Griess algebra's automorphism group
is generated by the visible group and the triality element), so it requires the CFSG library. `VOA` itself needs no
part of CFSG; there, `monstrousMoonshine` is stated with `GmatEqAutO` as a hypothesis.

**What is in here.** For `gmat_eq_griess` to apply by unfolding, our Monster structures must *be* CFSG's
(`Code.F4`, `Spin.SpinCoord`, `Code.Parker`, `Code.C`, `SpinLattice.phi0`). That is "Route A", which changes nine
Moonshine files; 85 Moonshine modules sit downstream of them on the way to the bridge. This library contains those 85
in their Route A form, renamed `VOA.Moonshine.X` → `MoonshineCFSG.X` (declaration names unchanged), plus the bridge.
76 of them are the library's files with only import lines renamed; nothing here imports VOA's own versions of the 85,
so no declarations clash. Everything else comes from `VOA` unchanged.

**Keeping the copies in step.** If one of those 85 files changes in `VOA/Moonshine`, mirror the change here.
`python3 MoonshineCFSG/check_mirror.py` (from the repository root) fails if any of the 76 verbatim copies has drifted.

**Build** (from this directory; dependency checkouts are shared with the parent via `packagesDir`):

```bash
lake exe cache get   # Mathlib's build cache
lake build
```

This downloads the full CFSG repository (about 22 GB with history) and compiles the about 20,000 CFSG modules that
`gmat_eq_griess` needs, since AxiomMath publishes no build cache: many hours, a lot of memory and tens of GB of disk.
The library `VOA` itself never needs this.
